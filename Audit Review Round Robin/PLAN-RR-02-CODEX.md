# Pusingan 2 (Pelan) — Codex

## Verdict keseluruhan

Pelan v1.0 mempunyai urutan yang munasabah dan majoriti rujukan kod tepat, tetapi belum selamat dijadikan runbook pelaksanaan tanpa pindaan. Saya meminta **pindaan substantif** pada F1 (kontrak ujian `skipRender()`), F2 (keadaan fokus/timer modal), F3 (skop ujian lokalisasi), F4 (cara override aksi Filament), F6 (denominator dan ambang metrik), F7 (API jadual sudah diketahui), serta urutan deploy/migrasi. Dakwaan “kesemua ID” juga perlu dilunakkan: dua ID sah-sihat tidak dipetakan kerana sudah ditutup, dan RR-11-04 bukan dua ID rasmi. Semakan ini 100% kod/vendor tempatan pada `8342d95`; tiada produksi disentuh.

## (c) Risiko tambahan

- **F0:** baseline boleh berubah jika kohort/persona tidak dibekukan; simpan manifest guide, route, role, viewport dan commit hash.
- **F1:** sifat `#[Locked]` tidak boleh dikemas kini sesuka hati dari klien pada fallback SPA; `skipRender` juga menangguhkan refresh badge `taskCount` yang dikira pada `HelpLauncher.php:67-83`. Auto-start daripada query mesti dinormalisasi/authorize semula melalui `findVisible()` setiap render.
- **F2:** timer 600 ms boleh menembak selepas langkah/tour ditutup; trap fokus boleh berkonflik dengan fokus sasaran dan modal Filament; `aria-modal` tidak serasi dengan interaction-enabled. Semua listener/timer mesti dibatalkan pada highlight berubah/destroy/minimize.
- **F3:** publish semua fail `lang/en` lalu mewajibkan parity penuh menjadikan setiap kemas kini framework satu kegagalan CI; refleksi semua Notification sukar kerana constructor/fixture/side effect berbeza. Perubahan locale boleh memecahkan assertion sedia ada dan snapshot.
- **F4:** pengesahan hanya pada create/save biasa boleh dipintas oleh `createAnother`, import/seeder/API/console. Kiraan Y boleh mahal dan boleh berubah antara dialog dan commit; query mesti tenant-scoped dan berdasarkan form state yang belum disimpan. Default DB false tidak mengubah factory/demo yang menetapkan true (`tests/Pest.php:39`, `DemoSeeder.php:126`).
- **F5:** bump `catalog_version` + sync index tanpa bump guide version mungkin tidak memaksa client/cache membaca copy baharu; sebaliknya bump per-guide mengulang auto-tour (`HelpLauncher.php:75-80`). Menukar `<div>` kepada `<main>` perlu pastikan tiada main bersarang pada semua slot guest.
- **F6:** atribut pada baris jadual/modal boleh hilang selepas Livewire morph; target tidak unik/tersembunyi boleh membuat resolver memilih elemen salah. Grep source tidak membuktikan target wujud di DOM atau unik.
- **F7:** pembaikan a11y via JS menyebabkan flash keadaan tidak patuh dan boleh hilang selepas morph; `aria-disabled` mesti seiring sifat native `disabled`, termasuk loading/error/non-PDF.
- **F8/deploy:** crawl produksi boleh menulis telemetri (pengajaran RR-11-01). Deploy app dahulu kemudian migrate berisiko kod baharu menyentuh skema lama; recreate nginx wajib setiap app replacement.

## (d) Reka bentuk alternatif

- **F1:** simpan satu objek konteks server-side terkunci (`originPath`, `requestedGuideId`, `requestedStep`) semasa `mount`; jangan cadang `$wire.set()` pada locked state. Asingkan listener telemetri kepada komponen/event endpoint yang tidak memerlukan morph jika pengoptimuman benar-benar diperlukan; konteks tersimpan sahaja sudah membetulkan punca.
- **F2:** jadikan `stepAdvancePlan()` fungsi tulen dan unit-test jadual keputusan (current/next/visibility/route/wait), kemudian e2e hanya flow utama. Auto-minimize berdasarkan `popoverRect` bertindih dengan modal/action target, bukan semata-mata target berada dalam modal.
- **F3:** salin empat fail locale yang memang dipakai tetapi uji parity terhadap subset kontrak aplikasi, bukan semua fail en terbitan vendor. Untuk e-mel, data-provider kelas notifikasi + factory eksplisit lebih stabil daripada refleksi automatik semua constructor.
- **F4:** override `getCreateFormAction()` dan `getSaveFormAction()` dengan `parent` action; condition closure membaca `$this->data['action']`. Tambah pengesahan yang sama pada create-another. Kiraan Y adalah maklumat sahaja; enforcement sebenar kekal validation/domain policy.
- **F5:** utamakan title eksplisit bagi kohort 124 langkah; gunakan `Str::limit(..., preserveWords:true)` hanya fallback bagi baki katalog. Ini mengelakkan heuristik koma/8 perkataan menghasilkan tajuk ganjil.
- **F6:** cipta registry PHP/JSON target yang dibaca test dan dokumentasi dijana daripadanya; e2e mengesahkan wujud, visible, unik, bukan generic untuk setiap target. Elak grep source sebagai source of truth.
- **F7:** gunakan API server-side `recordActionsColumnLabel('Tindakan')`; untuk link-name, hasilkan accessible name pada elemen pautan sebenar. JS hanya fallback vendor yang tiada hook.

## Jawapan 4 soalan terbuka

1. **`APP_FALLBACK_LOCALE=en`: sahkan.** Locale utama ialah ms; fallback en memberi mesej framework yang masih boleh difahami jika terjemahan tercicir. Menetapkan fallback sama dengan locale ms tidak menambah fallback dan kunci JSON literal EN tetap menjadi kunci. Namun ini bukan alasan menerima EN leak: parity kontrak + render tests mesti menjadi gate. Bukti mekanisme aplikasi: `config/app.php:82-85` membaca `APP_LOCALE`/`APP_FALLBACK_LOCALE`; ketiadaan `lang/ms` ialah finding audit.
2. **Ambang F6 kini tidak realistik/terdefinisi.** Output JSON sebenar ialah 68 guide app/433 langkah, bukan 25/124. Bekukan kohort audit 25/124. Cadangan gate W1: semua langkah tindakan dalam route W1 mesti target spesifik, dan kiraan kohort turun sekurang-kurangnya sebanyak langkah yang dimigrasi (baseline/target ditentukan selepas inventori, bukan meneka ≤50). W2/W3: sasaran akhir ≤25/124 generic-resolved hanya jika inventori membuktikan 25 langkah konsep memang wajar; setiap baki generic mesti ada justifikasi allowlist.
3. **Filament v4 praktikal:** override `getCreateFormAction()`/`getSaveFormAction()`, return `parent::...()->requiresConfirmation(condition)->modalDescription(...)`; tambah override create-another. API ini nyata dalam vendor. Jangan bina Action baharu dan jangan panggil `->action(...)` semula. Jika modal confirmation tidak dapat mengakses state dengan stabil, fallback checkbox `accepted_if` lebih selamat tetapi UX kurang kemas.
4. **600 ms tidak wajar sebagai konstanta tanpa bukti.** Ia terlalu singkat untuk membaca dan cukup panjang untuk race selepas pengguna bergerak. Pilih mekanisme overlap-aware selepas satu `requestAnimationFrame`/transition settle; auto-minimize hanya apabila popover benar-benar menutup target tindakan. Jika produk tetap mahu masa baca, gunakan 1.5–2 s yang boleh dibatalkan serta butang manual, dan ukur e2e dengan fake clock—bukan `waitForTimeout(600)`.
